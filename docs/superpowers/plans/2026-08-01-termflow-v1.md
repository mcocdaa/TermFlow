# TermFlow V1 Implementation Plan Set

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Deliver the approved TermFlow V1 as three sequential, independently testable implementation plans.

**Architecture:** Build the versioned wire protocol and single-process Control Plane first, then implement the per-Instance tmux Node and Bridge, then prove the complete enrollment-to-remote-input path with real tmux and deployment artifacts. Each plan ends in a working verification boundary and must be completed in order.

**Tech Stack:** Python 3.12, uv workspace, Pydantic 2, FastAPI, SQLAlchemy 2 with SQLite, asyncio, websockets/httpx, Typer, tmux 3.2+, pytest, Docker Compose.

## Cross-plan completion command

After all three plans:

```bash
uv run --all-packages pytest -q
uv run --all-packages ruff check .
uv run --all-packages mypy packages/protocol/src apps/control-plane/src apps/node/src
docker compose -f deploy/compose.yaml config --quiet
```

Expected: every command exits 0; the test summary contains no failed, error, or skipped
required end-to-end tests.

## Requirement coverage

| Approved requirement | Owning plan and task |
| --- | --- |
| Versioned A/B/C-compatible protocol | Control Plane Tasks 1-2 |
| One-time enrollment and scoped credentials | Control Plane Tasks 3-4; Node Task 1 |
| One `termflow new` equals one independent Instance | Node Tasks 2, 7-9 |

| B outage does not stop local tmux; automatic reconnect | Node Task 5; Delivery Task 2 |
