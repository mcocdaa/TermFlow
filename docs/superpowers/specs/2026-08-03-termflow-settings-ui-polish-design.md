# TermFlow 设置与双重因素认证 UI 精简设计

日期：2026-08-03  
状态：已确认，待实现

## 目标

设置和双重因素认证页面默认只展示用户完成操作所需的标题、字段、状态和控件。补充说明通过 `?` 图标按需展示，避免技术说明占据主界面。

## 界面主题

- 设置页中的每个主题选项继续等宽铺满容器。
- 色点和主题名称作为一个整体在选项内水平、垂直居中。
- 顶部导航中的紧凑主题选择器保持现有布局，不受设置页专用居中规则影响。

## 中继服务器

- `服务网址` 是代码框的正式字段标题，不作为独立散落文字。
- 标题行由 `服务网址` 和二维码图标组成；下方是网址代码框与复制按钮。
- 二维码说明不再展示协议版本等实现信息。仅在确有操作帮助时使用 `?` 图标。

## 双重因素认证设置卡片

- 卡片标题保持 `Two Factor Authentication / 双重因素认证`。
- 未绑定验证器时，主界面只保留必要状态和“激活双重因素认证”操作；功能解释放入 `?` 帮助提示。
- 已绑定时采用视觉方案 B：标题右侧形成紧凑操作组，依次显示“验证器已绑定”状态和“重新配置”操作。
- “启用双重认证登录”、帮助图标和开关保持为独立设置行。
- 帮助气泡以完整设置行为定位边界，允许换行，并限制在卡片可视宽度内；鼠标悬浮、键盘聚焦和触屏点击均能获取说明。

## 双重因素认证详细页

- 删除“管理员 Token 只用于本次验证，不会保存在客户端。”。
- 删除不影响用户操作的介绍段落和实现说明。
- 保留步骤名称、字段标签、扫码或手工输入所需的信息、一次性验证码要求、错误消息和完成状态。
- 可选背景说明放入 `?` 图标，不替代必需的字段标签、错误反馈或过期警告。
- “返回设置”和主要操作继续使用统一控件高度。

## 帮助提示规则

- 主界面不直接展示协议、密钥存储、Token 保存方式等实现细节。
- 会改变用户下一步操作的信息必须直接展示，不能藏进提示。
- 解释概念或后果的信息使用统一的圆形 `?` SVG。
- 提示框必须支持换行、键盘焦点和窄屏，不得造成水平滚动或溢出卡片。

## 非目标

- 不修改 TOTP API、验证流程或服务器安全策略。
- 不修改中继服务器 URL 来源。
- 不增加新的帮助弹窗系统；复用现有 `CircleHelp` 和 tooltip 模式。
- 不改变顶部导航和终端页面布局。

## 验证

- 组件测试覆盖主题内容居中所需 class、服务网址字段结构、方案 B 的标题操作组、非必要文案移除和帮助提示结构。
- 响应式契约测试覆盖 tooltip 以设置行作为定位容器、允许换行且不超过卡片宽度。
- 执行 client-ui 全量测试、类型检查和 Web 构建。
- 在桌面与窄屏视口检查设置页无水平溢出，二维码和帮助提示继续使用当前主题。
