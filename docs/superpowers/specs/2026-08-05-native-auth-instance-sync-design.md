# TermFlow 原生授权闭环与 A 实例同步设计

## 背景

当前 TermFlow 已有 Web C、Tauri 原生客户端和 A 节点的基础实现，但存在四类不一致：

1. Web C 登录页暴露了不应放在登录页的设备授权入口。
2. Tauri 的浏览器回调和设备码轮询没有统一的状态、持久化和成功反馈，Windows 上审批完成后不能可靠进入已登录状态。
3. 设备授权页的布局和移动端折叠不一致，操作按钮层级混乱。
4. A 会保留远程已删除或本地运行时已失效的旧实例，用户无法安全清理，也看不出 B 的连接状态。

本设计只覆盖授权体验、授权状态闭环、A 实例状态同步和相关可验证性；不改变终端内容传输协议、不把终端内容持久化到 B，也不重新设计 B 的管理员登录策略。

## 目标

- Web C 登录页只负责管理员 Token 登录。
- Web C 的设备审批入口位于“设置 → 已授权客户端”。
- Tauri 保留两条同等重要的登录路径：本机浏览器回调和跨设备设备码授权。
- 两条路径共享明确的授权状态机，审批成功后写入平台凭据存储、显示现有底部 Toast，并进入控制中心或原目标路由。
- 设备授权页在桌面端使用左右分栏，移动端自动上下排列；返回和重新生成按钮位于左侧内容块底部并排居中，设备码旁直接显示复制 SVG。
- A 提供显式 `sync`、安全 `prune` 和不删除数据的 `doctor` 状态检查；远程删除的 Term 不再作为可用实例显示。
- 通过单测、组件测试、构建和真实浏览器/Windows 安装包验证完整授权链路。

## 用户流程

### Web C 登录

`/login` 只保留管理员 Token 登录。页面不显示设备授权链接；设备审批页仍可通过受保护路由或设置入口访问，未登录时回到登录页并保留待处理上下文。

### Tauri 首屏

`/connect` 显示服务器地址和两个并排按钮：

- **浏览器登录**：打开系统浏览器，完成管理员登录和当前客户端审批。
- **设备码授权**：跳转到 `/connect/device`，不打开本机浏览器。

窄屏时两个按钮垂直堆叠，但顺序不变；两者不假定 Web C 和 Tauri 位于同一台设备或同一网络。

### Tauri 浏览器登录

1. 先注册 `termflow://auth/callback` 深链监听器。
2. 生成 PKCE、state、DPoP 参数并打开授权 URL。
3. Web C 完成管理员登录和客户端审批。
4. 系统浏览器回调到 Tauri；客户端校验 scheme、host、path、state 和 transaction_id。
5. Rust 交换短期访问凭据，写入平台 keyring。
6. 状态变为 `connected`，调用共享底部 Toast，然后进入原目标路由；没有目标路由时进入控制中心。

### Tauri 设备码授权

1. 进入 `/connect/device` 后立即请求并生成设备码和主题色二维码。
2. 页面左侧显示服务器地址和“等待审批”状态；右侧显示二维码、设备码和复制 SVG。
3. Tauri 按服务端 interval 轮询 token：`authorization_pending` 继续，`slow_down` 增加间隔，`access_denied` 和 `expired_token` 终止。
4. Web C 在“设置 → 已授权客户端”点击“授权新客户端”，弹出小型弹窗输入设备码并确认。
5. 审批完成后 Tauri 收到 token，写入平台 keyring，显示底部 Toast 并进入控制中心或原目标路由。
6. 返回连接、重新生成或离开页面会取消旧轮询，禁止并行会话。

设备授权页只保留必要内容：标题、服务器地址、二维码、设备码、剩余时间、审批状态和两个操作按钮。具体 Web C 操作路径不在页面正文重复说明；如需帮助，使用悬浮提示。

## 共享授权状态与组件边界

### `packages/client-core`

增加统一授权状态/结果类型，并让浏览器回调和设备码会话都输出相同的状态序列：

```text
idle → requesting → pending → approved → connected
```

终态还包括 `denied`、`expired`、`cancelled` 和 `network_error`。轮询器继续由平台注入等待函数和请求函数，不在共享核心内部拥有平台定时器。

授权成功必须通过 `CredentialVaultPort` 写入凭据；Tauri 使用平台 keyring 适配器，启动时尝试恢复未过期凭据。内存 vault 仅允许用于单测或无持久化的测试运行时。

### Web C

- 复用 `AuthorizedClientsPanel`、共享 Dialog、底部 Toast、主题色二维码组件。
- 登录页移除设备授权入口；设备审批表单只在已授权客户端弹窗中出现。
- 审批成功后关闭 Dialog、刷新已授权客户端列表并显示“已授权”。

### Tauri

- `NativeConnectView` 只负责服务器地址和两种路径选择，不承载设备码详情。
- `NativeDeviceAuthorizeView` 只负责设备码展示、状态订阅、取消/重新生成和成功导航。
- 回调监听、token 交换、keyring 写入和轮询由共享授权核心及 Tauri adapter 组合完成。
- 错误映射按阶段区分：网络不可达、深链监听失败、回调校验失败、审批拒绝/过期、token 交换失败；日志记录结构化事件，不把 token、验证码或私钥写入日志。

## A 实例同步与清理

### 本地状态

每条实例记录保留本地运行状态（tmux、bridge）、远程状态（online/offline/remote_deleted/unknown）和最近同步时间/错误。终端内容不进入同步数据。

### 命令语义

- `termflow sync`：显式请求 B 的当前实例/Term 清单；将远程不存在的本地记录标记为 `remote_deleted`，同步失败时保留原记录并报告原因。
- `termflow list`：快速读取本地记录，显示本地运行状态、远程状态和最近同步时间，不因网络请求阻塞。
- `termflow prune [--dry-run] [--force]`：只处理已标记 `remote_deleted` 或本地确认 tmux/bridge 均已失效的记录。默认展示候选并要求确认；`--dry-run` 不写入；`--force` 跳过交互确认。
- `termflow doctor`：检查 Python、tmux、配置权限、B 连通性、实例运行状态和最后同步结果；不自动删除记录。

清理只删除 A 的本地元数据和可安全关闭的本地 bridge，不删除 B 上的 Term，也不使用宽泛的进程杀死或状态目录递归删除。

## UI 布局与可访问性

- 首屏和设备授权页使用现有设计 token、卡片、输入框和按钮样式。
- 页面外壳固定标题栏和导航；只有当前内容区在溢出时滚动。
- 设备授权页桌面端左右分栏；移动端在 700px 左右断点折叠为上下两块。
- 设备码复制按钮是紧贴设备码的 SVG 图标，提供 `aria-label` 和复制成功 Toast。
- 返回/重新生成按钮在左侧内容块底部居中；不同时出现“取消”“返回连接”等同义按钮。
- 解释性文字默认隐藏在悬浮提示中，正文只保留完成任务所需信息。

## 测试与验收

### 单元和组件测试

- 共享授权状态机覆盖 pending、slow_down、denied、expired、取消、网络失败和重复轮询保护。
- Tauri 覆盖深链合法/非法 state、监听器失败、token 交换失败、设备码自动生成、重新生成取消旧会话和 keyring 恢复。
- Web 覆盖登录页无设备授权入口、已授权客户端弹窗、审批成功关闭/刷新/底部 Toast。
- A 覆盖 sync 标记远程删除、prune dry-run/确认/force、doctor 状态分类。

### 构建和真实验收

- 构建 Linux、Windows、Android 和 iOS Tauri 目标。
- 使用真实浏览器验证 Web C 管理员登录、Tauri 浏览器回调和跨设备设备码授权两条链路。
- 在 Windows 安装包中验证审批成功后自动进入控制中心，重启后仍保持登录，并检查 `termflow-client.log` 能区分各授权阶段。
- 运行 A 的 `sync/list/prune/doctor`，确认远程删除的 Term 不再被当作可用实例。

## 非目标

- 不把 Web C 登录改成设备码登录。
- 不把终端内容持久化到 B。
- 不改变 A 的终端尺寸权威关系和既有终端协议。
- 不在本轮引入新的 OAuth 服务或第三方 MFA 服务。
