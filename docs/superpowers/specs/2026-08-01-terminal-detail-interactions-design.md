# TermFlow 终端详情交互改进设计

## 目标

在不修改 A、B 或终端协议的前提下，统一控制中心统计卡和终端详情标题栏的交互，使可点击、可展开及快捷键提示行为清楚且一致。

## 已确认交互

1. 控制中心的四张统计卡都具有相同的悬浮、键盘聚焦和说明提示。`24 小时交互` 解释统计口径；`Computers` 解释注册总数及在线数量。
2. 终端详情页左上按 `终端名称 / 电脑名称 / 连接状态` 排列。终端名称和电脑名称保持同一行并在空间不足时截断，不通过换行占用标题栏高度。
3. 删除独立的铅笔编辑按钮。终端名称本身使用与电脑管理名称相同的可点击编辑模式；点击名称进入输入态，保存、取消、Escape 和现有校验/API 行为不变。
4. `显示`、`tmux 操作`、`聚焦 Pane` 三个桌面工具面板由终端详情页统一管理，只允许一个处于展开状态。打开另一个面板时，之前的面板立即收起；再次点击当前按钮则关闭当前面板。
5. tmux 操作列表的按钮正文只显示功能名称，不显示快捷键。快捷键来自 B/A 当前上报的绑定，不硬编码；鼠标悬浮或键盘聚焦按钮时显示自定义提示，并以 `<code>` 视觉样式呈现可读形式，例如 `Ctrl + b`。未上报绑定时提示 `未绑定`。
6. 移动端快捷操作抽屉保持现有展开和收起方式，不纳入桌面三个工具面板的互斥状态。

## 组件边界

- `DashboardView.vue` 负责为四张统计卡提供动态说明文案，`MetricCard.vue` 继续负责统一的提示和交互样式。
- `TerminalView.vue` 持有唯一的桌面工具面板状态，并把受控状态传给三个菜单。
- `TerminalTitlebar.vue` 负责同一行身份信息、名称编辑入口和 `显示` 菜单受控状态。
- `DisplayMenu.vue`、`TmuxActionMenu.vue`、`PaneFocusMenu.vue` 变为受控桌面菜单；选择操作或按 Escape 时向父层请求关闭。
- `TmuxActionMenu.vue` 负责把服务端绑定转换成面向用户的快捷键提示，不改变发送到终端的语义动作。

## 可访问性与错误处理

- 四张统计卡均可通过键盘聚焦并使用 `aria-describedby` 读取说明。
- 可点击终端名称使用按钮语义和明确的 `aria-label`。
- 三个菜单按钮继续维护准确的 `aria-expanded`。
- 快捷键提示同时支持 `:hover` 和 `:focus-visible`，通过 `role="tooltip"` 与操作按钮关联。
- 名称保存失败仍回滚原名称并显示现有错误信息。

## 验证

- Vitest 覆盖四张统计卡提示、名称即编辑入口、同一行布局契约、三个菜单互斥，以及快捷键只存在于悬浮提示中。
- 运行 Web 全量单元测试、类型检查和生产构建。
- 用新构建的隔离 Docker 实例进行桌面浏览器验收，不操作当前 `127.0.0.1:8765` 服务及其数据。
