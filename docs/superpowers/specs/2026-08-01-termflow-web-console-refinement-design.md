# TermFlow Web 控制台细节修整设计

## 目标与边界

本轮修整 B 内置 Web C 的登录、控制中心、电脑管理、添加电脑和导航体验。继续保持
A 为 tmux/PTY 与终端尺寸权威、B 为认证和统一时间记录方、C 为展示与控制入口；不改变
Term/Window/Pane 模型，不让 C 修改 A 的终端尺寸，也不引入 Agent 功能。

## 登录页

- `/login` 使用独立的简洁布局，不显示全局顶栏、主题选择器、侧栏或移动导航。
- 页面只保留标题“登录”、标签“管理员令牌”、密码输入框和“登录”按钮；删除“安全会话”、
  浏览器存储说明以及“创建会话”文案。
- 保留现有安全行为：管理员令牌只提交一次，提交后立即清空，不写入 URL、localStorage、
  sessionStorage 或日志；失败时显示不包含令牌的错误。

## 控制中心指标与 Term 列表

- “在线 Terms”和“活动 Panes”指标卡增加统一主题驱动的悬浮、键盘聚焦和按下反馈。
- 两张卡在悬浮或聚焦时显示简短说明：“当前在线并可远程控制的 Term”和“在线 Term 中
  当前处于活动状态的 Pane”；在线 Term 说明同时包含总 Term 数。提示层不遮挡关键数据，
  并使用 `aria-describedby` 让键盘用户可读取。
- Term 列表采用用户选择的方案 A：每个 Term 是独立圆角卡片，卡片之间留出固定间距。
  在线卡片整块可点击，悬浮/聚焦时轻微提亮并上浮；离线卡片不可跳转，降低强调但保留
  状态信息。所有颜色只使用现有主题变量和 `color-mix`，三个主题保持一致。

## 电脑管理列表

- 桌面表格固定为四列中文标题：“名称”“终端”“最近在线”“注册时间”。删除“操作系统”
  列；名称单元格继续显示可点击编辑的电脑名称和已有 hostname。
- “终端”列只显示一个圆角状态胶囊。存在在线 Term 时显示绿色点和“在线 (N)”；没有在线
  Term 时显示中性色点和“离线 (0)”，不再显示“N 个在线 Term”和另一个重复状态。
- 所有表头和单元格在各自行内垂直居中；最近在线与注册时间各自只占一列。
- 删除“注册和最近在线时间由 B 记录，按当前设备时区显示。”说明文字。
- 窄屏继续退化为单列信息块，并通过字段标签保留四列语义，不依赖被隐藏的桌面表头。

## 时间语义

- B 继续以 UTC 记录 Installation 的创建时间和最后在线时间，并通过带时区 ISO 8601
  字符串传输；A 的本地时钟不参与这两个时间值。
- C 不传入固定 `timeZone`，由浏览器使用运行设备的本地时区。中文格式固定为
  `2026年8月1日 11:21` 这一类年月日和 24 小时时分，不显示 `GMT+8`、`UTC`、`CST`
  等时区后缀。
- 因此同一 B 记录在不同 C 设备上可以显示不同当地时间，这是预期行为。

## 两阶段添加电脑

- 弹窗标题始终为“添加电脑”，右上角保持 Lucide `X` 关闭按钮；删除“一次性注册”眉题。
- 初始阶段依次显示“电脑名称”标签、占位文字“输入电脑名称”的输入框和“创建”按钮。
  名称使用现有可编辑名称契约：1–128 个字符，拒绝控制字符；无效时不调用 API。
- `POST /api/v1/enrollment-tokens` 接受可选 `display_name`。Web C 必须发送用户输入的名称；
  保留可选性是为了兼容现有 CLI 和无请求体调用方。
- B 只把预设显示名与注册码哈希一起保存，不提前创建 Computer。A 首次成功消费注册码时，
  B 原子取出预设显示名并创建 Installation：`display_name` 使用预设名称，`hostname` 仍使用
  A 实际上报的主机名。这样失败或过期的注册码不会留下幽灵 Computer。
- SQLite 启动迁移为现有 `enrollment_tokens` 增加可空 `display_name`；旧码和 CLI 生成的码
  没有预设名称时继续回退到 A 上报 hostname，再回退到“Computer”。
- 创建成功后切换到注册码阶段：标题和关闭按钮不变；显示“此注册码只显示一次……”倒计时、
  “注册码”代码框、“终端执行”标题及帮助按钮、命令代码框和“复制命令”按钮。
- 60 秒自动刷新时沿用同一个电脑名称重新申请注册码。关闭弹窗仍不会撤销已经复制的码；
  B 的首次消费或到期时间是唯一失效依据。
- 帮助提示定位在“终端执行”标题行的可用宽度内并向下展开，桌面和移动视口都不得超出或被
  弹窗裁切；鼠标悬浮和键盘聚焦均可显示。

## 导航图标

- 桌面侧栏“控制中心”左侧使用 Lucide `LayoutDashboard`，“电脑管理”左侧使用 Lucide
  `MonitorCog`。图标与文字共用当前颜色和激活态，不硬编码主题色。
- 移动底部导航复用相同图标和可访问名称，避免桌面与移动表达漂移。

## 错误处理与可访问性

- 添加电脑请求失败时保留名称输入或当前有效状态，显示安全错误并允许重试；请求进行中禁用
  重复提交。
- 弹窗继续支持初始聚焦、Tab 焦点约束、Escape 关闭和关闭后焦点恢复。阶段切换后焦点移到
  新阶段第一个有意义的控件。
- 指标提示、侧栏图标和状态点都不单独承担唯一语义；可访问名称始终包含文字。

## 验证与交付

- Protocol/Python 测试覆盖注册名称验证、兼容无请求体签发、名称随注册码原子消费、旧数据
  迁移和单次消费竞争。
- Vitest 先失败再实现，覆盖极简登录布局、指标提示与状态、方案 A 卡片结构、四列表头及
  垂直布局契约、本地时间无时区后缀、两阶段弹窗、自动刷新沿用名称和侧栏 Lucide 图标。
- Playwright 使用全新隔离 B 数据库和端口，在桌面与移动视口验证登录、添加电脑两阶段、
  帮助提示边界、表格布局、指标悬浮和 Term 卡片悬浮，并保存截图。
- 完整运行 Python 测试、Ruff、Mypy、Web Vitest、TypeScript 类型检查、生产构建和 Compose
  配置检查。通过后重建并替换本地 B 容器，复用现有数据卷，确认健康检查和 A 自动重连。
